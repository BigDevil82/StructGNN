# Experiments

本目录当前同时承载了两类内容：

- `research`: 论文相关的研究脚本，如消融、指标统计、绘图、分析
- `pipelines`: 已经逐渐演变为正式流程的案例推理与建模链路

现阶段为了降低整理风险，暂不直接大规模移动已有实现文件，而是先明确分区原则。

## 当前分区约定

### 研究脚本

以下目录属于研究脚本范畴，允许保留一定的临时性：

- `ablation/`
- `analysis/`
- `metrics/`
- `plots/`

这些目录中的代码主要用于：

- 论文实验
- 指标统计
- 图表绘制
- 对比分析

### 正式流程候选

以下目录不再视为单纯实验脚本，而是后续准备抽离的正式流程：

- `case_study/`

`case_study/` 当前已经承载了：

- 模型推理
- 预测结果后处理
- FEM 拓扑构建
- ETABS / 盈建科桥接

因此后续应逐步迁移到独立的流程目录，而不是继续向 `experiments/` 深度堆积。

## 本阶段整理策略

当前阶段仅建立骨架，不做高风险迁移：

1. 保持现有 import 路径可用
2. 不移动 `case_study/` 现有实现文件
3. 先通过文档和占位目录明确后续落点
4. 新增相关能力时，优先判断其属于 `research` 还是 `pipelines`

## 后续目标结构

后续可逐步收敛为类似结构：

```text
experiments/
├── research/
│   ├── ablation/
│   ├── analysis/
│   ├── metrics/
│   └── plots/
└── pipelines/
    └── case_study/
```

在真正迁移前，应先完成：

- 入口梳理
- 依赖梳理
- 兼容层设计
- 最小验证脚本
