为了能够灵活地扩展多种优化算法（GA、PSO、贝叶斯优化等），并且代码具有良好的复用性，我们需要抽象出**优化问题**的统一接口。下面我从**输入输出定义**、**核心抽象类设计**、以及**具体算法适配方式**三个方面给出方案。

---

## 一、 优化问题的共同输入与输出

无论是哪种优化算法，它们要解决的是同一个底层问题：**在给定的布局和设计条件下，寻找一组构件尺寸参数，使得目标函数最小（或最大），同时满足规范约束**。

### 1.1 输入（固定部分）
- **布局拓扑**：已转换为json格式，可读取并建模分析。
- **设计条件**：总层数、层高、地震烈度、场地类别、设计地震分组。
- **优化参数**: 上中下三个标准层剪力墙厚度、主梁宽、高、次梁宽、高、混凝土等级共8个。
- **参数空间**：每个决策变量的类型（离散/连续）、取值范围。对于剪力墙尺寸，变量是离散的（墙厚、梁高、混凝土等级等），需要定义每个变量的可选离散值列表。
- **目标函数**：通常为材料用量（混凝土+钢筋）最小化。
- **约束函数**：包括整体指标（层间位移角、周期比、剪重比、扭转位移比、刚度比等）和构件指标（轴压比、剪压比等），由OpenSees分析后计算得到。

### 1.2 输入（算法特定参数）
- 种群大小（GA/PSO）、迭代次数、交叉/变异概率、学习因子等。
- 贝叶斯优化的采集函数类型、初始采样点数等。
- 这些参数属于算法配置，不是优化问题的固有属性。

### 1.3 输出
- **最优解**：一组决策变量的取值（如 `{tw_bot:250, tw_mid:200, tw_top:180, ...}`）。
- **最优目标值**：对应的材料用量。
- **可行性信息**：该解是否满足所有约束。
- **优化历史**（可选）：每一代的最优解、目标值、收敛曲线等。

## 二、 核心抽象类设计（Python）

为了实现可扩展性，建议定义以下几个抽象基类（不一定按照如下签名，可自行调整）：

### 2.1 `OptimizationProblem`（问题定义）

```python
from abc import ABC, abstractmethod
from typing import Dict, List, Any, Tuple

class OptimizationProblem(ABC):
    """定义优化问题的输入、变量、目标、约束"""
    
    @property
    @abstractmethod
    def variables(self) -> List[Dict[str, Any]]:
        """返回决策变量列表，每个变量包含：name, type('discrete'/'continuous'), domain(列表或区间)"""
        pass
    
    @abstractmethod
    def evaluate(self, x: Dict[str, Any]) -> Tuple[float, bool, Dict[str, float]]:
        """
        评估一组变量取值。
        返回: (目标函数值, 是否可行, 约束违反详情字典)
        """
        pass
    
    @abstractmethod
    def get_constraints_violation(self, x: Dict[str, Any]) -> Dict[str, float]:
        """返回各约束的违反程度（正值表示违反，0表示满足）"""
        pass
```

### 2.2 `Optimizer`（算法基类）

```python
class Optimizer(ABC):
    def __init__(self, problem: OptimizationProblem, config: Dict[str, Any]):
        self.problem = problem
        self.config = config
    
    @abstractmethod
    def optimize(self) -> Tuple[Dict[str, Any], float, List[Dict]]:
        """
        运行优化，返回:
        - best_solution: 最优变量字典
        - best_objective: 最优目标值
        - history: 每代记录（可选）
        """
        pass
```

### 2.3 具体实现示例

- **GA优化器**：继承 `Optimizer`，内部使用 `pymoo` 或 `deap`，调用 `problem.evaluate`。
- **贝叶斯优化器**：继承 `Optimizer`，内部使用 `optuna`，同样调用 `problem.evaluate`。

这样，当需要增加新算法时，只需实现新的 `Optimizer` 子类，而 `OptimizationProblem` 保持不变。

## 三、 数据流与代码复用结构

### 3.1 整体流程

```
布局+设计条件 → 构建OptimizationProblem → 实例化具体Optimizer → 运行优化 → 输出最优解
```

### 3.2 关键点：如何实现 `evaluate` 方法？

`evaluate` 方法内部需要：
1. 将变量 `x` 转换为完整的模型配置（包括三段墙厚、梁截面、混凝土等级等）。
2. 调用 OpenSees 分析。
3. 从分析结果中计算：
   - 目标函数（材料用量）。
   - 约束违反（位移角超出量、轴压比超出量等）。
4. 返回 (目标值, 是否可行, 违反详情)。


### 3.3 并行评估支持

由于 `evaluate` 可能很慢，优化器应支持并行评估多个候选解。可以在 `Optimizer` 基类中增加 `parallel_evaluate` 方法，或者利用 `joblib`/`ray` 在 `problem.evaluate` 外部实现并行。推荐在具体优化器中实现，因为不同算法的并行策略不同（GA天然适合批量评估，贝叶斯优化则需要顺序评估）。

## 四、 变量编码与约束处理

### 4.1 变量编码

对于离散变量，优化算法通常需要连续编码（如0~1之间的浮点数）或者直接使用离散值。建议在 `OptimizationProblem` 中提供编码/解码方法：

```python
def encode(self, x: Dict) -> np.ndarray:
    """将变量字典转换为连续向量（供算法使用）"""
    pass

def decode(self, vector: np.ndarray) -> Dict:
    """将连续向量转换回变量字典"""
    pass
```

GA/PSO可以使用编码后的向量，贝叶斯优化也可以使用编码后的连续空间。

### 4.2 约束处理方式

- **罚函数法**：在目标函数中加入惩罚项：`objective + penalty * sum(violations)`。简单通用，但需要调整惩罚系数。
- **约束支配法**：在多目标优化（如NSGA-II）中，直接比较解的可行性，可行解总是优于不可行解。这需要算法支持约束处理。
- **修复法**：对于简单的约束（如墙厚非递增），可以在 `decode` 后强制修正（例如 `x['tw_mid'] = min(x['tw_mid'], x['tw_bot'])`），这样算法搜索空间更规整。

推荐结合使用：**修复简单约束 + 罚函数处理复杂约束**。
