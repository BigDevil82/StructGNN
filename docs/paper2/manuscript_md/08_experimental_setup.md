# 3. Experimental Setup

本节介绍实验数据、代理模型训练与优化对比的设置。与第 2 节的方法定义不同，本节的重点是说明实验对象如何构成、各类模型在什么数据上训练和验证，以及后续结果将围绕哪些核心问题展开。具体数值结果和现象分析放在第 4 节讨论。

## 3.1 Dataset and Structural Evaluation Settings

实验数据基于 143 张剪力墙结构布局图纸构建。这些布局给出了剪力墙和梁的布置位置，来源于建筑设计院工程师提供的结构方案，因此可以作为具有工程合理性的初始结构布置。按照前序布局生成研究中的条件划分方式，样本可根据设防烈度和建筑高度组合分为三类设计条件。Group7-H1 对应设防烈度 7 度、PGA 为 0.10 g 且建筑高度 $H \le 50$ m 的低密度需求组；Group7-H2 对应相同设防烈度但建筑高度 $H>50$ m 的中等需求组；Group8 对应设防烈度 8 度、PGA 为 0.20 g 的高需求组。该分组反映了抗震需求和结构高度对剪力墙布置及截面设计的共同影响。

布局图纸只确定了结构几何和构件布置。为了形成可用于监督学习的数据，还需要为每个布局指定截面、材料和设计条件参数。本文采用拉丁超立方采样在参数空间内生成候选设计方案，每个布局采样约 5000 个样本。采样参数覆盖墙厚、梁截面、混凝土强度等级、楼层数和抗震设计条件等关键因素，具体范围见表 1。对于存在竖向分区的墙厚参数，采样后保持上部墙厚不大于下部墙厚，以符合常规结构设计逻辑。

| Parameter | Symbol | Unit | Sampling values |

| Number of stories | $N$ | - | 18-33 |
| Story height | $h_{story}$ | m | 2.9 |
| Bottom wall thickness | $t_{w,b}$ | mm | 200, 250, 300, 350, 400 |

对于每个布局和参数组合，本文使用 OpenSeesPy 自动建立结构分析模型并执行结构评价。剪力墙采用 MVLEM 类单元建模，分析过程包括静力分析和模态分析。静力分析用于获得主要竖向和水平作用下的结构响应及构件内力，模态分析用于提取周期等整体动力特性。随后，根据结构响应指标和构件内力完成墙、梁构件的设计校核与配筋计算。荷载工况组合可在附录中以表格形式列出，正文中仅保留与代理标签构造有关的说明。

上述结构评价流程为代理模型提供两个核心监督标签。第一个标签为 `final_pass`，表示候选结构是否同时满足分析收敛性、整体响应限值和构件设计要求。第二个标签为 `material_steel_kg`，表示该结构经分析和设计后得到的总钢筋用量。前者直接对应优化过程中的不可行方案筛选，后者对应材料造价预排序中最难快速获得的连续变量。

最终数据集包含约 715,000 个真实有限元分析样本。模型训练时采用 layout-level split，即以布局为单位划分训练集、验证集和测试集，避免同一布局的参数变体同时出现在不同数据子集中。当前实验划分为 100 个训练布局、21 个验证布局和 22 个测试布局，对应约 0.70:0.15:0.15 的布局比例。测试布局来自 L17、L27 和 L1L28 三个布局族，用于评估代理模型对未见布局的泛化能力。

## 3.2 Surrogate Model Training Settings

代理模型实验围绕两个全局任务和两个局部校准任务展开。全局任务使用完整训练集学习跨布局预测能力，局部校准任务则在测试布局内模拟优化过程中逐步积累 FEA 样本后的校正效果。这样的组织方式对应本文方法中的两级代理思想：全局模型提供初始预测，局部模型利用当前布局上的少量真实样本修正偏差。

全局可行性代理模型以 `final_pass` 为目标，输入为 room graph、全局布局统计特征和设计参数。该模型采用 LayoutParamGNN 架构，输出候选方案通过综合校核的概率。训练损失为带类别权重的 binary cross entropy，以缓解可行和不可行样本比例不均衡的问题。模型选择时关注其作为筛选器的表现，即在保持较高 feasible recall 的前提下尽可能提高不可行候选的拒绝比例。为了说明图表征的作用，可行性任务同时设置表格模型和不同输入表征的 baseline。

全局钢筋代理模型以 `material_steel_kg` 为目标，采用与可行性模型一致的 LayoutParamGNN 输入架构。钢筋用量经过对数变换和标准化后进行回归训练，损失函数采用 Smooth L1 loss。由于该模型在优化中服务于候选排序而非最终材料统计，训练后的评价不仅关注绝对误差，也关注候选方案之间的相对排序能力。钢筋任务的 baseline 包括 parameter-only 模型、parameter + layout statistics 模型以及常规表格回归模型，用于判断图结构信息是否带来额外收益。

局部可行性校准实验以全局可行性模型的测试集预测为基础，在每个测试布局内抽取少量样本作为局部校准集，并在剩余样本上评估概率校准和筛选效果。比较方法包括 Platt scaling、isotonic regression、local logistic calibration、概率残差修正和 ensemble vote correction。该实验用于回答全局概率在特定布局上是否存在可校正偏差，以及少量布局内 FEA 样本能否改善保守筛选。

局部钢筋校准实验以全局钢筋模型预测为基准，学习真实钢筋用量与全局预测之间的残差。残差校准模型使用设计变量和全局预测作为输入，比较 Ridge、Gaussian process、LightGBM、KNN 和小型 MLP 等候选模型。该实验关注局部残差校准是否能降低布局级系统误差，并提高候选造价排序的可靠性。

## 3.3 Optimization Benchmark Settings

优化实验用于检验代理模型是否能在真实结构优化流程中降低 FEA 开销。实验比较的基准方法为 full FEA optimization，即优化算法产生的每个候选方案都经过完整 OpenSees 分析和规范校核。本文方法则在候选进入 FEA 前引入校准代理模型：首先利用可行性模型筛掉低可行性候选，再利用校准后的钢筋预测和快速混凝土估计形成材料造价排序，从而将有限的 FEA 预算分配给更有希望的方案。

主实验采用遗传算法作为优化器，因为截面和材料参数均为离散变量，遗传算法能够自然处理这类组合搜索问题。每个候选方案的最终适应度仍由真实 FEA 结果决定；代理模型只影响候选是否被送入真实评价。为了考察方法的普适性，实验还可扩展到 PSO 和 random search。PSO 用于检验代理筛选在不同群体更新机制下的适用性，random search 用于分离“优化算法搜索能力”和“代理预算分配能力”的影响。

优化测试布局从未参与代理模型训练的测试集中选取。主实验覆盖 L17、L27 和 L1L28 三个布局族，每个布局族选取 5 个布局，并对每个布局运行 5 个随机种子。为了避免不同方法之间受到设计条件差异影响，同一 layout-seed 组合下的设防烈度、场地类别和地震分组在所有对比方法中保持一致。主实验中，L17、L27 和 L1L28 分别对应设防烈度 7.0、7.5 和 8.0。

代理辅助方法与 full baseline 在相同搜索空间、相同随机种子和相同优化预算下比较。所有方法的最终最优方案必须经过真实 FEA 和设计校核确认。被代理模型筛掉或因预算分配未进入 FEA 的候选方案只参与当前批次的搜索排序，不作为真实可行解或最终设计结果。

## 3.4 Evaluation Metrics

本文的评价指标围绕三个问题组织，而不是对每个模型罗列大量统计量。第一个问题是全局代理模型是否具备足够的初始预测能力。对于可行性代理模型，主要关注 PR-AUC 和 conservative screening performance。PR-AUC 反映类别不平衡条件下模型区分可行样本的能力；筛选性能由 reject rate 和 feasible recall 共同描述，前者表示可提前跳过的候选比例，后者表示真实可行候选被保留的比例。对于钢筋代理模型，主要报告 MAE、$R^2$ 和 ranking accuracy。MAE 和 $R^2$ 衡量回归精度，ranking accuracy 衡量模型是否能正确比较候选方案钢筋用量高低，这与优化中的候选预排序直接相关。

第二个问题是在线局部校准是否能改善全局模型在单个布局上的可靠性。可行性校准主要使用 Brier score 和 screen recall 描述概率校准质量与筛选安全性；钢筋残差校准主要使用 MAE、bias 和 ranking accuracy。这里的 bias 尤其重要，因为全局钢筋模型在某些布局上可能出现系统性高估或低估，而局部残差模型正是为修正这种布局相关偏差而设计。

第三个问题是代理辅助优化是否真正提高了结构优化效率。优化结果主要报告真实 FEA 调用次数、可行解成功率、首次发现可行解所需 FEA 次数以及最终材料造价。FEA 调用次数反映计算成本，可行解成功率和首次可行解 FEA 次数反映搜索有效性，最终材料造价用于判断代理筛选是否损害设计质量。对于同一 layout-seed 组合，代理辅助方法与 full FEA baseline 进行成对比较；当二者均找到可行解时，比较最终造价差异；当 full baseline 也未找到可行解时，该 case 主要用于分析布局或搜索空间本身的难度。
