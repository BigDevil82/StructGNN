如下是一个完整的**数据生成管线方案**，涵盖输入定义、输出指标、参数组合策略、数据存储格式以及并行化实现细节。目标是：**可扩展、可复现、信息完整**，为后续代理模型/监督学习/强化学习提供高质量数据集。

---

## 一、 输入定义（自变量）

每个样本的输入由三部分组成：**布局选择、尺寸参数、设计条件**。

### 1.1 布局选择
- 来源：142套平面布置图纸（假设为CAD或图像，需先转化为结构模型）。  
- 已经将每套图纸生成了一个结构拓扑描述文件（JSON），包含节点坐标、剪力墙、连梁（分主梁、次梁），存储在“data\dxf\cad_json_data\fem_raw”文件夹中。  

> 在参数化生成时，只需指定布局的ID（即文件名）。

### 1.2 尺寸参数（可变量）
遵循“三段式”分段规则（底部、中部、顶部）。

| 参数名 | 符号 | 单位 | 取值范围（离散） | 说明 |
|--------|------|------|------------------|------|
| 底部墙厚 | `tw_bot` | mm | [200, 250, 300, 350, 400] | 底部加强区 |
| 中部墙厚 | `tw_mid` | mm | [160, 180, 200, 250, 300] | 但必须 ≤ tw_bot |
| 顶部墙厚 | `tw_top` | mm | [160, 180, 200, 250] | 必须 ≤ tw_mid |
| 主梁高度（连梁） | `hb_main` | mm | [400, 500, 550, 600, 650, 700] | 跨高比经验值限制 |
| 主梁宽度 | `bb_main` | mm | [200, 250, 300, 350] | 常与墙厚协调 |
| 次梁高度 | `hb_sec` | mm | [300, 400, 450, 500] | 次梁用于楼板分块 |
| 次梁宽度 | `bb_sec` | mm | [200, 250, 300] | 一般不小于200 |
| 楼板厚度 | `hs` | mm | [100, 120, 150] | 根据跨度 |
| 底部混凝土等级 | `conc_bot` | - | [C30, C35, C40, C45, C50] | |
| 中部混凝土等级 | `conc_mid` | - | [C30, C35, C40, C45] | 必须 ≤ conc_bot |
| 顶部混凝土等级 | `conc_top` | - | [C30, C35, C40] | 必须 ≤ conc_mid |

> **梁的主次梁划分**：  
> - 输入的布局文件中已经标注了哪些是主梁，哪些是次梁, "beam_role": "primary/secondary"。

### 1.3 设计条件（全局）

| 参数名 | 符号 | 取值范围 | 说明 |
|--------|------|----------|------|
| 总层数 | `N` | [18, 33] 整数 | |
| 标准层层高 | `h_story` | 2.8~3.0 m | 可固定为2.9 |
| 地震烈度 | `intensity` | [6, 7, 7.5, 8] | |
| 场地类别 | `site_class` | [I0, I, II, III, IV] | |
| 设计地震分组 | `group` | [1, 2, 3] | |

### 1.4 参数组合生成策略

**每个布局独立采样**，以覆盖该布局下的不同设计条件。总样本数 = 布局数 × 每布局采样数。

- **采样方法**：拉丁超立方采样（LHS）或随机采样。因为参数有离散值，可以先将每个离散值映射为整数索引，然后对索引进行LHS，再映射回离散值。  
- **约束处理**：生成时直接剔除违反“墙厚非递增”、“混凝土等级非递增”的组合。  
- **每布局样本量**：建议 **500** 组。142×500 = 71,000 次分析。
- **并行批次**：将每个布局的所有参数组合一次性生成，然后分配到多个计算节点。

## 二、 输出定义（因变量）

通过OpenSees分析（弹性反应谱+静力工况），需要记录以下指标，**既要满足规范校核，又要为代理模型提供丰富特征**。

### 2.1 整体指标

| 指标 | 符号/说明 | 用途 |
|------|-----------|------|
| 总质量 | `mass_total` (t) | 地震力计算基准 |
| 前6阶周期 | `T1~T6` (s) | 判断刚度、扭转 |
| 周期比 | `Tt/T1` (扭转/平动) | 规范限值 ≤0.9 |
| 最大扭转位移比 | `torsion_ratio` | 规范限值 ≤ 1.5 |
| 最小剪重比 | `base_shear / (mass_total*g)` | 规范限值（如0.016~0.032） |
| 最大层间位移角 | `max_drift_ratio` (rad) | 规范限值 1/1000 |
| 最小刚度比（相邻层） | `stiffness_ratio` | 避免软弱层 |
| 是否满足规范 | `feasible` (bool) | 分析成功标志 |
| 配筋设计是否通过 | `design_passed` (bool) | 无失败墙梁时为True |
| 材料用量（混凝土） | `material_concrete_kg` | 全部墙梁混凝土总质量 |
| 材料用量（钢筋） | `material_steel_kg` | 全部墙梁钢筋总质量 |

### 2.2 构件级指标

为了后续约束校核（如轴压比、连梁抗剪）以及可能的配筋设计，需要输出每个关键构件的内力或响应。

- **每片剪力墙肢**：  
  - 最大轴压比 `n_max` 
  - 最大剪压比 `v_max`
- **每根连梁（主梁）**：  
  - 最大剪压比 `v_max`


> 由于构件数量不定，输出格式应灵活：例如用字典 `{wall_id: n_max, beam_id: V_max}` 存储。

## 三、 数据存储方案

### 3.1 存储格式

推荐 **Parquet** 或 **HDF5**，两者都支持列式存储、高效压缩、快速读写。  
- 每个布局一个文件，如 `layout_001.parquet`，包含该布局下所有样本的行。  
- 每行对应一个样本（特定参数组合），列包含输入参数和输出指标。

### 3.2 数据表结构（列名示例）

| 列名 | 类型 | 说明 |
|------|------|------|
| `layout_id` | str | 布局标识 |
| `sample_id` | int | 样本编号（布局内唯一） |
| `tw_bot`, `tw_mid`, `tw_top` | int | 墙厚(mm) |
| `hb_main`, `bb_main`, ... | int | 梁尺寸 |
| `conc_bot`, ... | str | 混凝土等级 |
| `intensity`, `site_class`, `group`, `N` | float/str | 设计条件 |
| `T1`...`T6` | float | 周期(s) |
| `max_drift_ratio` | float | 最大层间位移角 |
| `feasible` | bool | 是否满足所有规范 |
| `design_passed` | bool | 配筋设计是否通过（无失败墙梁） |
| `design_failed_beam_count` | int | 设计失败梁数量 |
| `design_failed_wall_count` | int | 设计失败墙数量 |
| `material_concrete_kg` | float | 墙梁总混凝土质量 |
| `material_steel_kg` | float | 墙梁总钢筋质量 |
| `converged` | bool | OpenSees是否收敛 |
| `wall_axial_ratios` | json str | 墙肢轴压比字典 |
| `wall_shear_ratios` | json str | 墙肢剪压比字典 |
| `beam_shear_ratios` | json str | 连梁剪压比字典 |
| ... | ... | 其他整体指标 |

> **注意**：对于变长的构件级数据，可以用JSON字符串存储。

### 3.3 元数据记录

另存一个 `metadata.json`，记录：
- 参数取值范围  
- 布局与拓扑文件的对应关系  
- OpenSees版本、分析设置（阻尼比、模态数等）  
- 生成时间、并行配置

## 四、 并行化实现方案

### 4.1 整体架构

采用 **生产者-消费者** 模式：
- **生产者**：读取布局列表，为每个布局生成参数组合（N组），放入任务队列。
- **消费者**：多个工作进程（或机器）从队列中取出一个任务（布局ID + 参数组合），运行完整的OpenSees分析，将结果写入共享存储。

### 4.2 技术选型

- **单机多进程**：使用 `multiprocessing.Pool`，每个进程独立调用OpenSees。适合几百核的服务器。
